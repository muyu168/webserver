# WebServer — 高性能 C++ HTTP 服务器

基于 Linux 的高性能 Web 服务器，从零手写，采用 **Epoll ET + Reactor + 线程池** 架构，经过多轮性能调优后，高并发场景 QPS 达 **16 万+**。

---

## 技术架构

```
                  ┌─────────────────────────────┐
  新连接请求  ───▶ │  WebServer（主线程）          │
                  │  Epoll ET 事件循环            │
                  │  小根堆定时器（超时连接管理）    │
                  └───────────┬─────────────────┘
                              │ 投递任务
                  ┌───────────▼─────────────────┐
                  │  ThreadPool（工作线程 × N）   │
                  │  解析 HTTP 请求 / 构建响应     │
                  └───────────┬─────────────────┘
                              │ eventfd 通知主线程
                  ┌───────────▼─────────────────┐
                  │  异步日志（双缓冲 + 后台线程）  │
                  └─────────────────────────────┘
```

---

## 核心模块

| 模块 | 实现要点 |
|------|---------|
| **Epoll** | ET 边缘触发，非阻塞 I/O，最大连接数 65535 |
| **线程池** | 默认 8 线程，`std::future` 获取任务结果，条件变量阻塞等待 |
| **HTTP 解析** | 有限状态机（FSM）增量解析，支持 GET/POST，HTTP/1.1 Keep-Alive |
| **定时器** | 小根堆 + `unordered_map`，O(log n) 增删，定时清理空闲连接 |
| **异步日志** | 双缓冲设计（当前缓冲 + 备用缓冲），后台线程批量落盘，减少锁竞争 |
| **信号处理** | `signalfd` + Epoll 统一事件源，优雅关闭服务器 |
| **线程通信** | `eventfd` 通知主线程处理工作线程的待发送响应，避免跨线程直接操作 socket |

## 关键设计思路

**为什么用 Epoll ET 而不是 LT？**
ET 模式只在状态变化时通知一次，强制一次性读完所有数据，减少 epoll_wait 调用次数，在高并发下系统调用开销更低。配合非阻塞 I/O，循环 read 直到返回 EAGAIN，确保数据不丢失。

**为什么用 eventfd 做线程间通信？**
工作线程处理完请求后需要通知主线程发送响应，不能直接在工作线程中写 socket（非线程安全）。eventfd 可被 Epoll 监听，写入通知后主线程在事件循环中统一处理响应队列，保持单线程操作 socket。

**双缓冲日志的优势？**
前端写日志时只需加锁追加到当前缓冲，后台线程定期（3秒或缓冲满时）将缓冲区整体交换并落盘。相比每条日志都 write() 到文件，大幅减少 I/O 次数和锁持有时间，对业务线程的性能影响极小。
